# compact2binary

**Convert compact multi-response survey data into a clean binary (0/1) indicator matrix — driven entirely by a codeframe, validated end to end.**

![python](https://img.shields.io/badge/python-3.10%2B-blue)
![license](https://img.shields.io/badge/license-MIT-green)
![tests](https://img.shields.io/badge/tests-pytest-brightgreen)

Multi-response survey questions ("select all that apply") are commonly stored in a **compact** layout — a few columns holding the *codes* a respondent picked. Most analysis, cross-tabulation, and modelling instead needs a **binary** layout — one 0/1 column per possible answer. Doing that expansion by hand is slow, error-prone, and easy to get subtly wrong (dropped codes, off-by-one mentions, silent unknown values).

`compact2binary` automates the expansion, keeps everything else in the file untouched, and **QCs its own output** so mistakes surface loudly instead of slipping into a deliverable.

> **Note on data:** this repository is a clean-room implementation. Every dataset here is **synthetic**, generated by `faker` (see `scripts/generate_synthetic_data.py`). It contains no real respondents, clients, or proprietary content. The survey theme (snack brands) and all values are invented.

---

## What it does

Given compact input like this:

| respondent_id | weight | Q1 | Q3_m1 | Q3_m2 | Q3_m3 | Q4        |
|---------------|--------|----|-------|-------|-------|-----------|
| R00001        | 1.62   | 2  | 7     | 6     | 1     | 1;2;3;6;7 |

it produces binary output like this:

| respondent_id | weight | Q1 | Q3_1 | Q3_2 | … | Q3_7 | Q4_1 | Q4_2 | … |
|---------------|--------|----|------|------|---|------|------|------|---|
| R00001        | 1.62   | 2  | 1    | 0    | … | 1    | 1    | 1    | … |

* **`Q3`** was stored as one column per *mention* (`Q3_m1…Q3_m6`) → expanded to one indicator per code.
* **`Q4`** was stored as a single *delimited* column (`"1;2;3;6;7"`) → expanded the same way.
* **`respondent_id`, `weight`, `Q1`** (single-response) pass through unchanged.

## Features

- **Codeframe-driven.** Nothing survey-specific is hard-coded. A single YAML file describes every question; the same engine handles any survey.
- **Two compact storage layouts.** Multi-column ("one column per mention") *and* delimited ("codes joined in one cell").
- **Passthrough-safe.** IDs, weights, single-response questions, and open-ends are carried through in their original order, untouched.
- **Built-in QC.** An independent validator re-reads the input and checks the output for unknown codes, unparseable tokens, round-trip count mismatches, and non-binary values — returning a structured report and a non-zero exit code for CI.
- **Correct missing-data handling.** Choose per question whether a blank answer means "selected nothing" (`0`) or "not asked / off-base" (`NaN`).
- **Value-labelled columns.** Name indicators `Q3_krunch` instead of `Q3_4` with `--labels` (or a `{label}` template) for self-documenting output.
- **Exclusive-code integrity check.** Declare a "None of these" code as exclusive; the validator flags any respondent who picks it *and* a real option.
- **Penetration stats.** A `stats` command emits per-code frequencies and percentages, weighted when you supply a weight column.
- **CSV, TSV & Parquet.** Read and write any of them; the format is chosen from the file extension.
- **Runnable out of the box.** A synthetic data generator means you can clone and run the whole pipeline in under a minute.

## Quickstart

```bash
# 1. Install
pip install -e ".[dev]"

# 2. Generate a synthetic compact dataset (500 fake respondents)
python scripts/generate_synthetic_data.py --rows 500 --seed 42 \
    --out data/synthetic_compact.csv

# 3. Convert compact -> binary, and QC the result
compact2binary convert \
    -i data/synthetic_compact.csv \
    -c config/codeframe.example.yaml \
    -o data/synthetic_binary.csv \
    --validate
```

Expected tail:

```
Wrote 500 rows x 21 cols -> data/synthetic_binary.csv
Validation: PASS
  respondents: 500
  multi_questions: 2
  indicator_columns: 17
```

More of the CLI:

```bash
# Human-readable labelled columns, written to Parquet, with inline QC
compact2binary convert -i data/synthetic_compact.csv \
    -c config/codeframe.example.yaml -o data/binary.parquet --labels --validate

# Weighted per-code penetration table
compact2binary stats -i data/binary.parquet \
    -c config/codeframe.example.yaml --weight weight --labels
```

Prefer the Python API?

```python
from compact2binary import load_codeframe, convert, validate
import pandas as pd

codeframe = load_codeframe("config/codeframe.example.yaml")
compact   = pd.read_csv("data/synthetic_compact.csv", dtype=str)

binary = convert(compact, codeframe)          # -> a new DataFrame
report = validate(compact, binary, codeframe) # -> structured QC report
assert report.ok, report.summary()
```

Or run the full illustrated demo: `python examples/example_run.py`.

## How it works

### The codeframe is the single source of truth

Every survey specific lives in `config/codeframe.example.yaml`. To process your own survey, copy that file and edit it — you never touch the conversion code.

```yaml
questions:
  - id: Q3
    label: "Which snack brands have you bought in the last 3 months?"
    type: multi
    storage: multi_column                       # one column per mention
    columns: [Q3_m1, Q3_m2, Q3_m3, Q3_m4, Q3_m5, Q3_m6]
    codes: {1: Crispa, 2: Muncho, 3: Snaxi, 4: Krunch,
            5: Nibblz, 6: Poppa, 7: Zesti, 8: Grainly}

  - id: Q4
    label: "Which snack brands are you aware of?"
    type: multi
    storage: delimited                          # codes joined in one cell
    column: Q4
    delimiter: ";"
    codes: {1: Crispa, 2: Muncho, 3: Snaxi, 4: Krunch,
            5: Nibblz, 6: Poppa, 7: Zesti, 8: Grainly}
```

### Output column naming

Indicator columns are named with the `output_template` (default `"{qid}_{code}"`), so `Q3` code `4` becomes `Q3_4`. Source mention columns are named distinctly (`Q3_m1…`) precisely so inputs and outputs never collide.

### Validation / QC

The validator is deliberately **independent** of the converter — it re-parses the compact input rather than trusting the conversion, so it can actually catch conversion bugs. It reports:

| Check | Meaning |
|-------|---------|
| Unknown codes | A code appears in the data but not the codeframe (stale codeframe / upstream recode bug). **Error.** |
| Exclusive-code co-occurrence | A code marked `exclusive` (e.g. "None of these") appears alongside other codes. **Error.** |
| Unparseable tokens | A cell isn't an integer code (e.g. `"x"`, `"2.5"`). **Warning**, token ignored. |
| Round-trip mismatch | Indicators set ≠ distinct known codes selected, per respondent. **Error.** |
| Domain violation | An indicator isn't `0`, `1`, or a deliberate `NaN`. **Error.** |

Try it: generate data with `--dirty` to inject anomalies and watch QC fail with a non-zero exit code:

```bash
python scripts/generate_synthetic_data.py --rows 100 --dirty --out data/dirty.csv
compact2binary convert -i data/dirty.csv -c config/codeframe.example.yaml \
    -o data/dirty_binary.csv --validate   # -> Validation: FAIL, exit 1
```
